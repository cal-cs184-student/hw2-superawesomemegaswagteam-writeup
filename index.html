Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm evaluates a Bezier curve at a parameter t by repeated linear interpolation. Given n control points, we lerp each adjacent pair at t, pi' = (1-t) pi + t pi+1, which gives n-1 new points. Repeating this on the new points shrinks the list by one each level until a single point remains, and that point is on the curve at t.

In BezierCurve::evaluateStep we implemented one level of this: loop over adjacent pairs of the input points, push the lerp of each pair into a result vector, and return it. The existing render code calls it once per press of E and uses the member variable t.

My curve has 6 control points, so there are 5 levels. The figures show the starting points, each level, the finished curve, and the curve after moving control points and changing t.

Part 2: Bezier surfaces with separable 1D de Casteljau

A Bezier patch is a grid of control points with two parameters, u and v. Because the surface is separable, we apply 1D de Casteljau twice. First we evaluate each row of control points at u, which gives one point per row. Then we treat those points as a new curve and evaluate it at v. The result is the surface point at (u, v).

we implemented this with three functions. evaluateStep is the same lerp step as Part 1 but on 3D points with t passed in. evaluate1D copies the points and calls evaluateStep until one point is left, then returns it. evaluate calls evaluate1D on every row with u, collects the results, and calls evaluate1D on them with v.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

Vertex::normal() walks every face around the vertex with h = h->twin()->next(). For each non-boundary face it takes the three corner positions and adds cross(p1 - p0, p2 - p0) to a running sum. The length of that cross product is twice the triangle's area, so larger triangles contribute more and no separate area computation is needed. The sum is normalized at the end.

Part 4: Edge flip

flipEdge takes the two triangles that share an edge and replaces that edge with the other diagonal of the quad they form. It does not create or delete any elements. It only reassigns pointers, so it runs in constant time. Boundary edges are skipped.

Because every pointer has to be right, we wrote down all the halfedges, vertices, edges and faces involved before and after the flip, then set every pointer for each of them, including the ones that do not change. A single stale pointer shows up later as a crash or a missing triangle when the mesh is traversed.

Debugging: One problem we faced was fixing the halfedge pointers but forgetting a vertex's or face's own halfedge() pointer. After a flip, a vertex could still point to a halfedge that now belonged to a different vertex. The flip looked correct on screen, but the next walk around that vertex, such as computing vertex normals with Q, followed the wrong loop and crashed or shaded oddly. Flipping the same edge twice and checking that the mesh returned to the original, and stepping around the edge with N and T, caught this quickly.

Part 5: Edge split

splitEdge inserts a new vertex at the midpoint of an interior edge and connects it to the two opposite vertices, turning the two triangles into four. This creates 1 vertex, 3 edges, 2 faces and 6 halfedges. The original edge and its two halfedges are reused for the half of the edge that touches the first endpoint. Boundary edges are ignored.

One easy mistake is the halfedge pointer of the second endpoint. It used to point at the halfedge that now starts at the new vertex, so it has to be reassigned. The new vertex's halfedge is set to point along the original edge, as the assignment asks, and the function returns the new vertex.

Debugging: One problem we faced was wiring only one side of a new twin pair, or forgetting to repoint a neighbor's next. A single split looked fine, and the crash only appeared when a second split or flip touched the same triangles. That is why we tested splits and flips right next to each other, as in the last figure below, and why check_for was useful for finding which elements still pointed at a halfedge that had been rewired.

Part 6: Loop subdivision for mesh upsampling

upsample works in five steps. First, we compute the new position of every original vertex, (1 - n u) p + u (sum of neighbors), with u = 3/16 for degree 3 and 3/(8n) otherwise. Second, we compute the position for each edge midpoint, 3/8 (A + B) + 1/8 (C + D). Third, we split only the original edges, using a count taken before splitting so the new edges are not split again. Fourth, we flip every new edge that connects one old and one new vertex. Fifth, we copy the stored positions into the vertices. All positions are computed on the untouched mesh and only written at the end, since changing a vertex early would corrupt the later calculations.

Debugging: One problem we faced was that new edges are appended to the end of the edge list, so a loop that ran until edgesEnd() while splitting kept finding the edges it had just created and never finished. The loop has to run over the original edge count only, with the next iterator saved before each split. A second slip was writing positions before all splits were done, which gave a lopsided mesh. Applying every position at the end is what keeps repeated subdivisions smooth, as in the two teapot levels below.

Cube: sharp corners and asymmetry

Sharp corners and edges are smoothed away. Each corner is pulled toward its neighbors, so the cube shrinks and turns into a rounded blob. The result is also not symmetric. Each cube face is two triangles split along one diagonal, and every face has the diagonal in the same direction, so some corners have more edges than others. Those corners are pulled differently, which makes the subdivided cube lopsided.

Pre-processing for symmetric subdivision

The fix is to split the diagonal of each of the six faces before subdividing. Every face then has a center vertex with four triangles around it, all faces are triangulated the same way, and every corner has the same degree. Loop subdivision preserves that symmetry, so the cube subdivides evenly. Splitting edges near a corner before subdividing also puts more vertices close to it, so the corner is rounded off less.
